# Privacy and publication model

## Session-derived identity

Only the deployment's Convex Auth JWT provider is accepted. A verified token identifies a component session, not a client-selected user; every app operation resolves that live session and the app-owned user, so sign-out/revocation immediately denies old access tokens. Development password identities and their media/avatar/push access are allowed only under exact `TAKE_DEPLOYMENT_ENV=development`, including sessions issued before a mode change. Apple start/completion reject missing or placeholder credentials. Onboarding cannot create a second identity or reactivate a tombstone.

Deletion checks the current session's immutable creation time within five minutes, not token issue/refresh time or a client claim. A single transaction tombstones the account, revokes all sessions/refresh tokens and schedules batched cleanup. Minimal app/method bindings remain reserved, and every new sign-in callback rejects deleted/deleting/disabled users. Account cleanup does not claim to delete the person's Apple account. Core `auth:isAuthenticated` reports session existence; app availability is independently enforced by `viewer:session` and all content entry points.

The iOS OAuth relay has one fixed custom-scheme destination, no storage/logging, strict nonce/code shape checks, 400/no redirect on malformed input and no-store/no-referrer responses. The app checks its saved relay nonce; Convex Auth separately validates the saved OAuth state and one-time ticket. No password, JWT or refresh credential travels in the relay URL. Credential values, callback query strings and media grants must not appear in ingress logs.

## One authority for content

`convex/lib/access.ts` is shared by original reads, reply reads/counts, caption reads, grant issuance, each HTTP grant redemption and direct-reply notification eligibility. A friends original is owner-readable for history. Other viewers need the current round, a successful receipt in that exact round and an approved, unblocked friendship with its author. A pending request is never a friendship. A friends reply first passes its parent; A↔B must still be approved/unblocked, and a third viewer must be approved/unblocked friends with both A and B. Reply ownership permits deletion, not access to a hidden parent. Each response is built from viewer-visible records rather than returning raw database rows.

Casey (friends with Alex and Blair) can see Blair's reply on Alex's original after posting. Dana (only friends with Alex) sees Alex's original with zero visible replies and cannot redeem or obtain either asset of Blair's reply, read its caption or report it. Removing A↔B hides the exchange from normal playback for everyone. New-round opening relocks friends' content, including existing grants, while owners retain their own historical originals.

V4 adds explicit public audience, never an implicit migration of friends content. Only originals can choose it, defaults remain friends, and retries cannot switch an intent's audience. Replies inherit their parent's immutable audience and cannot supply their own. A public read still requires an active signed-in viewer's successful receipt in that exact round and no block with its author in either direction; replies and comments additionally check their own author's availability and blocks. Public direct reads may use an existing same-round receipt after the round changes, but For You has the current-round feed lock. For You excludes friends originals and the viewer's own take, and pagination/summary counts use only visible records.

Likes and battle votes are transactionally unique per viewer/item; every write rechecks current access. Like totals expose no identities. Comment text is trimmed and bounded, and a persistent per-user creation window prevents delete/recreate rate-limit bypasses. Friends comment visibility requires parent-first content access and a current approved/unblocked content-author/commenter relationship; third viewers must also be friends with both. Comment reports authorize the comment itself. Comment counts and cursors never include hidden commenters. Deletion permission for the commenter/content author does not grant permission to read an otherwise hidden parent.

Battle publication pairing is atomic, public-only and same-round, with a different option/author and no author-to-author block. Both sides must independently be visible for battle reads, voting and the opponent metadata in an original summary; hiding a side hides that metadata without leaking its ID/profile. Authors cannot vote and moving a vote cannot create a second vote. Deleting either side unlinks the battle and clears the survivor's battle metadata; scheduled cleanup removes votes, likes, comments and reports on the deleted conversation. Account tombstones hide authored content/comments before cleanup and also remove their interactions on other people's content.

## Actual bytes before atomic success

An authenticated expiring upload intent is unique per owner/request ID. A short lease prevents concurrent/replacement uploads. The HTTP route authorizes before reading a bounded body, hashes and stores those actual bytes, and binds the storage ID through an internal mutation. Public clients cannot assert a storage ID, duration, owner or verification result. A storage object whose binding loses a race is deleted; an aged-orphan sweep catches a process death between store and bind.

Finalization leases work, reads that bound object, verifies its hash, and checks its actual MP4/MOV structure inside Convex. Failed parsing never unlocks. The final mutation checks the lease, expiry, verified hash/metadata, current round, valid option, receipt uniqueness and relationship/parent access **again**, then writes exactly one immutable original+receipt or one reply and the idempotent upload result. Concurrent attempts conflict/retry under Convex serializable transactions. Retryable processing failures retain staging until expiry; a lost processing lease can be reclaimed. Client cancellation/deletion wins against stale processing. Terminal failures have no receipt.

Original deletion immediately hides its conversation, clears the receipt's original reference, unlinks its battle and schedules dependent reply/media/report/interaction cleanup. The receipt success fact persists and still unlocks the exact round while preventing republishing. Successful upload-result records persist for idempotency until account deletion. An old result is not authorization to read content that has since been deleted, blocked or relocked.

## Grant and avatar boundaries

Private URLs contain 256-bit random grant tokens; only SHA-256 hashes are stored. Each grant binds viewer/content/kind/asset and expires after 60 seconds. GET/HEAD re-evaluates active user and shared access; Range is checked only after authorization. There is no raw storage resolver, reusable private storage URL or redirect. Bodies and captions do not appear in locked envelopes. Responses are `private, no-store`, with no sniffing or referrer disclosure. A token URL is still a short-lived bearer capability: do not log it, and a recipient can retain bytes already received.

Minimal avatars are a distinct public-profile choice. Image intents are owner-private before binding; Convex checks JPEG/PNG structure, dimensions and hash. The selected public avatar preserves original bytes and MIME, including any metadata: there is no decoding, normalization or metadata stripping. The route serves only the active user's selected avatar, never an arbitrary storage object. Changing/deleting an avatar cleans the superseded asset. A leaked avatar URL cannot resolve video, thumbnails, captions, staging or user tokens.

## Bounded MVP policy

Video intent/body cap is **8 MiB**. Native exports a fast-start 720×1280 portrait H.264/AAC MP4, trimmed to at most 14.9 seconds. The bounded ISO-BMFF checker accepts MP4/MOV with one H.264 or HEVC video track and zero or one AAC track. It checks dimensions, rotation, exact sample-table duration of 3,000–15,000 ms before rounding, and sample/chunk ranges inside stored media data. A 2999.99 ms clip cannot round into acceptance. This deliberately reduced policy does not fully decode codecs, prove every payload is playable, require audio or prove audible/non-silent audio. No server thumbnail is generated; new assets return null while legacy thumbnail access remains guarded. HTTP raw bodies are counted independently of `Content-Length`; avatars cap at 2 MiB and 2048×2048. Verify runtime memory and bandwidth under load before increasing caps.

Intents last ten minutes; upload/processing leases last two minutes. There is no external media call. Expired staging/grants are swept every ten minutes in bounded batches. Unbound stored objects older than one hour are swept every twelve hours using indexed references; this preserves recent in-flight stores and published assets. Original cleanup hides immediately and removes dependent rows/assets in batches; account tombstones revoke authorization before asynchronous cleanup.

An account may have three active video intents, three active avatar intents, 200 approved friends, 100 outgoing/200 incoming pending requests, 500 own blocks, ten devices, 200 live media grants and 100 active reports. Conversations accept at most 50 stored replies; feed pages cap at eight originals, history at ten, replies at 50. These are explicit MVP safety bounds, including a serializable limit check at finalization. A deleted reply can free a reply slot; published originals and successful receipts remain immutable. Request-local authorization memoization keeps count/read queries within Convex transaction/index-range budgets without carrying authorization across requests. Do not remove the bounds or cache access globally without a new load/privacy review.

Public list queries use indexed seek scans and visible cursors, not unbounded global collections. Likes/votes use transactional totals; comment totals are per-author so availability, blocks and current friendships still filter counts. Current query safety budgets cover 512 scanned rows per public/comment page, 256 distinct comment authors per item, 256 checked pairing candidates across at most 16 other options and a shared 3,000-read visibility budget. Overflow returns retryable `LIMIT_REACHED`, never a partial list or fabricated/truncated count. Same-option pools do not consume the opposite-option pairing budget. These are MVP availability bounds, not a claim of unlimited public-feed scale.

Convex operations, parsing, stored clips and private playback incur service costs. Range/HEAD and lazy AVPlayer loading avoid eager downloads, but every authorized media request still rechecks the database and uses Convex bandwidth; there is deliberately no CDN cache. Live deployments require authenticated-ingress quotas/rate controls and monitoring. Application limits are not a substitute for provider-level abuse protection, a privacy retention policy, or real load testing.

## Verification scope

The automated Convex tests exercise actual auth component sessions, identity/profile/social/publication/account functions and registered HTTP routes with transaction limits, including production mode denial, reauthentication, relay validation, locked direct IDs/media, the Casey/Dana matrix, visible counts, legacy thumbnails, revocation, failed processing, concurrency, exact-round unlock, preserved receipts, new-round relock, Range/HEAD and cleanup. Media tests use the actual structural checker and synthetic FFmpeg-generated fixtures, not a decoder service. The retained historical worker tests do not describe the current publication policy. Apple cloud OAuth, hosted storage and physical capture/playback remain external launch checks. Remote push is unavailable and needs a future trusted APNs worker; successful push outcomes exist only in tests. No unavailable transcription is advertised as ready.
