# Production service integration

The wire reference is the shared TAKE integration contract and wire addendum v3, which supersedes earlier auth instructions. Demo identities and sample media never enter production services.

## Construction and authentication

`ProductionService` is `@MainActor` and is constructed lazily for live mode. `LiveConfiguration` requires distinct `CONVEX_URL` and `CONVEX_SITE_URL` HTTPS origins without paths, credentials, queries or fragments. Missing, unresolved or placeholder values fail closed. Demo startup constructs neither the production service nor its Convex clients. Only ConvexMobile **0.8.2** is pinned; provider private keys remain on the deployment.

Apple sign-in uses `ASWebAuthenticationSession`, not a native identity-token exchange. The client generates a random 43-character base64url relay nonce, calls `auth:startSignInWithApple({ redirectTo: "<site>/auth/ios?state=<relayNonce>" })`, and opens the returned redirect with callback scheme `take`. The fixed HTTPS relay forwards the code and nonce to `take://auth/convex`. The client validates the nonce before calling `auth:completeSignInWithApple({ state: <OAuth state>, code })`: the OAuth state returned by the start mutation is distinct from the relay nonce. Missing, mismatched, malformed or replayed callbacks must not be redeemed; cancellation leaves demo available.

Stock `@convex-dev/auth` 2.0.0 exposes the mutations `auth:startSignInWithApple`, `auth:completeSignInWithApple`, `auth:refreshSession({ refreshToken })`, `auth:signOut({ refreshToken })`, `auth:signUpWithUsernamePassword` and `auth:signInWithUsernamePassword`; there is no `auth:signIn`. Sign-in completes with `{ status: "complete", tokens }` or an error envelope; refresh returns `{ kind: "rotated", tokens }` or `{ kind: "noSession" }`. Tokens contain `accessToken`, `refreshToken`, `refreshTokenExpiresAt`, and `userId`. The labeled developer username/password screen launches only with `--development-auth` without `--demo`, outside normal and demo flows. Backend enforcement is authoritative: developer login and sessions must be rejected outside development.

Sessions are stored in the Keychain with `WhenUnlockedThisDeviceOnly` accessibility. The ConvexMobile 0.8.2 `AuthProvider` supplies access tokens to the client and rotates refresh tokens through `auth:refreshSession`. Transient refresh failures clear private access and subscriptions while preserving the owner's retry draft; permanent failures and sign-out end the session and clear its private state. Stale token callbacks cannot bind an earlier session to a newer one. Sign-out clears the local session and attempts remote revocation; do not log tokens.

For account deletion, establish a fresh session for the same account before `accounts:requestDeletion({})`. The server requires a session created within five minutes, and `REAUTH_REQUIRED` means sign in again and retry; token refresh does not reset session age. The backend owns identity verification and session revocation.

APNs registration defaults off. Permission is requested only after explanation; neither Firebase nor a push entitlement is required in the current configuration. If enabled in a future configured build, `devices:register` receives the APNs hex token and `devices:unregister` removes the installation. There is no remote push delivery provider. Sign-out cleanup is best effort, and notification taps refetch authorized state rather than trusting payload content.

Observe `.takePrivateAccessInvalidated` to clear players and private UI caches when access changes. `.takeSessionEnded` also signals a cleared service session. The service retains no private media grants or response disk cache; previously played bytes cannot be revoked.

## Transport and wire behavior

One-shot queries use cancellable subscriptions; Today has a retained subscription canceled by `stopWatching()`. Subscription, query and upload work and pending private state are canceled or invalidated on identity changes and sign-out.

`watchConversation(originalId:_:) -> () -> Void` watches authorized `takes:detail` and the first `replies:list` page (`cursor: null`, `limit: 50`), calling its data-free callback on updates or errors so the UI refetches and removes revoked content. Its returned closure cancels both subscriptions. `stopWatching()` and session invalidation cancel every retained Today, graph, and conversation watcher. `watchToday` also watches `friends:list`; graph changes after the initial emission, or graph watcher errors, post the private-access invalidation event even if safe Today presence data did not change.

DTOs decode directly into the domain models accepted in addendum v1, including the array returned by `friends:search`, the `blocked` list, and relationship literal `approved`. Void mutation/action acknowledgments accept any valid JSON result rather than assuming a null/string response. Pagination limits use `Double` so Convex receives ordinary JSON numbers, not encoded int64 values. ConvexError data is decoded as `ServiceFailure`; unknown failures get a generic connection error without logging tokens or HTTP bodies.

Video upload uses `uploads:begin` with the persisted draft UUID as `requestId`, then authenticated `POST /v1/uploads/<uploadId>/video` using the returned upload URL. Drafts must belong to the current backend viewer, must not be demo drafts, and must contain a camera-sourced local MP4 with video and audio. Bundled files and simulator-fixture sources are rejected. The client checks actual AVFoundation duration and byte count, applies the tighter returned limits with a 15,000 ms/8 MiB ceiling, snapshots the file, and streams it with URLSession. Capture exports ordinary MP4 through the H.264/AAC 720p preset, trims to 14.9 seconds to leave timing/padding margin, and caps export bytes at 8 MiB. Progress remains below 1 until the HTTP binding succeeds. Request redirects are refused; response bodies are bounded to 64 KiB; cookies, credentials, and URL caching are disabled. Temporary snapshots are protected and removed after completion/cancellation. Trusted backend validation is still mandatory; client checks are not authorization or proof of media provenance.

`uploads:finalize` is an action with the server upload ID; `uploads:status` is an owner query. Neither records a local successful receipt. Retries preserve the same draft request ID/upload ID and reconcile status/finalization before deciding whether bytes need another POST. Null progress is not evidence that bytes are missing: retryable verifier failures retain bound bytes, and a successful HTTP acknowledgment can be lost. Only an uploading-state finalization response of `INVALID_MEDIA` (the backend's missing-bytes signal) permits another POST; bound, processing, failed or already-published intents never get blindly reposted. Processing remains processing until the server returns a published result.

Video and thumbnail playback both call `media:createPlaybackGrant`. The client accepts only the configured site origin's `/v1/media/<grantId>?token=...` route and rejects raw storage/download URLs. Expiry is checked against the Today server-clock offset with five seconds of clock/response tolerance. The selected remote player and downloaded private file are cleared at the returned server-clock-adjusted deadline, including when paused inside AVPlayer's controls. A subsequent play requests a new grant. The backend enforces its actual at-most-60-second lifetime and current authorization on every request, including Range/HEAD. Captions call `captions:get`; only a ready response can contain nonempty caption text, with no fabricated fallback.

Avatar intents use the addendum envelope `{uploadId,uploadUrl,expiresAt,acceptedMimeTypes,maxBytes,maxWidth,maxHeight}`. Photos up to 20 MiB are decoded through bounded ImageIO thumbnailing off the main actor, orientation-normalized, stripped of metadata, and encoded as accepted JPEG/PNG within the tighter returned server limits. The current backend returns 2 MiB and 2048 squared; the returned byte limit is used during resize/export. The returned URL must be `POST /v1/uploads/<uploadId>/avatar` on the site origin. Its successful `{uploadId}` acknowledgement is checked before `profiles:update`. Passing null for `avatarUploadId` retains the current photo.

All social, profile, preferences, content deletion/reporting, device-token, and account-deletion calls use the named functions in the contract. Feed requests use eight records, history ten and replies fifty, and the UI follows nextCursor. A vanished feed/reply cursor restarts authorized reads from null rather than appending stale records.

One-shot queries/mutations have 30-second client deadlines, actions 60 seconds, HTTP uploads a 300-second resource deadline, and sign-out unregister/revocation five-second deadlines each. A timeout cannot undo a mutation already accepted by the server; status checks and idempotent request IDs are essential before retrying publication. Offline device unregister and session revocation are best effort; local cleanup still runs when the backend is unreachable.
